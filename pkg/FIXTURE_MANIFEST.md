# Go port coverage manifest

This maps the Quint **0.33.1** baseline in [BASELINE.md](BASELINE.md) to Go
validation. The inventory covers all **51** TypeScript `*.test.ts` files under
`quint/test`, the six Rust integration-test families, the four VSCode server test
families, and the integration transcript groups. It is a coverage map, not a
claim that every reference assertion has been replayed or that the port is done.
[PLAN_PORT.md](PLAN_PORT.md) records completion; [COMPATIBILITY.md](COMPATIBILITY.md)
records observable limits. [The per-fixture notes](testdata/parser/README.md)
identify generators and comparison boundaries in more detail.

**D** means actual saved reference output compared by Go tests; **U** means
focused Go unit/property/ownership tests; **C** means an explicitly enabled
corpus or live-reference check; **P** means pending evidence or an unsupported
boundary. A fixture count counts saved scenarios, not independent specifications,
assertions, coverage percentages, or successful live solver runs. Expected errors
are passing rejection tests only when the test asserts them; an oracle that is
merely saved is never a passing implementation test.

Run the normal Go suite from `pkg/` with the local checker workspace configured:

```sh
go test ./... -count=1
go vet ./...
```

The default suite uses saved reference output; it does not start Node, Rust,
Scala or Java. Build/reference-tool dependencies and the aggregate one-second
test-runtime target are separate concerns. No skipped test counts as a pass.

Comparison rules belong to each reader. Older parser fixtures normalize documented
IDs/generated names, while the newer raw-ID/source and CLI schema fixtures compare
those fields directly. Exact wire tests compare the original raw JSON rather than
remarshaling both sides through Go types; otherwise omitted/empty fields can be
lost on both sides and hide a mismatch. Dynamic durations, absolute paths, ANSI
color and unsupported reference errors are adjusted only where a reader explicitly
documents the boundary. A normalized comparison never establishes raw equality.
